## Bloqueadores (deben resolverse pre-merge)

### B1. CSP bloquea Capacitor/Android — feature roto en runtime

`apps/web/index.html` CSP `connect-src 'self' ...` no incluye `https://acars.pub`.

- En web (origin `https://acars.pub`): `'self'` cubre `/api/notifications/*` → funciona.
- En Android/Capacitor (origin `capacitor://localhost`): `'self'` ≠ `https://acars.pub` → **POST a `/api/notifications/register|unregister|send` bloqueado por CSP**.

`api.ts:getNotificationsApiOrigin()` retorna `https://acars.pub` para Capacitor (líneas 65-81), confirmando que la intención es cross-origin. Pero el CSP no lo permite.

**Fix**: añadir `https://acars.pub` a `connect-src` en `index.html`. 1 línea.

### B2. `functions/` no tiene cobertura CI — verde del PR falso para el Worker

- `functions/` **no es workspace** (sin `package.json`).
- CI usa `pnpm -r test` → solo corre tests de workspaces.
- `apps/web/vitest.config.ts` tiene `include: ["src/**/*.test.*"]` → excluye `functions/`.
- **Resultado**: los 432 LOC de tests del Worker (`functions/api/notifications/[[path]].test.ts`) **nunca se ejecutan en CI**.
- Lo mismo para typecheck y lint: `functions/` no se valida.

**Verifiqué manualmente** (vitest con config ad-hoc, node 22): 4/4 tests del Worker pasan. El código está bien, pero **cualquier modificación futura al Worker entra sin verificación**.

**Fix**: crear `functions/package.json` + añadir `"functions/*"` a `pnpm-workspace.yaml` + ajustar CI. O mover el test a `apps/web/src/` con mock del PagesFunction.

### B3. `importance` de Android notification channels fuera de rango

`provider.tsx` líneas 32-57 declara `importance: 5,4,4,3`. Android `NotificationManager.IMPORTANCE_*` es **0-4** (NONE/MIN/LOW/DEFAULT/HIGH). No hay `IMPORTANCE_MAX=5`.

`MainActivity.java` (líneas 33-58) usa `IMPORTANCE_HIGH/DEFAULT/DEFAULT/DEFAULT` (4/3/3/3) — **inconsistencia**.

Cuando Capacitor `PushNotifications.createChannel` se llama desde JS, sobrescribe los canales Java con importance inválida → comportamiento impredecible (clamp a HIGH o rechazo).

**Fix**: alinear valores. Probablemente el intent era `critical=4 (HIGH), competition/progression=3 (DEFAULT), operations=2 (LOW)`. Corregir `provider.tsx` a `[4,3,3,2]` y `MainActivity.java` a `IMPORTANCE_HIGH/DEFAULT/DEFAULT/LOW`.

## Lo excelente (destacar)

### Seguridad del Worker (1236 LOC) — impecable

- **NIP-98 HTTP auth completo** (líneas 171-234): kind 27235, ±60s timestamp window, validación de URL firmada, method firmado, hash SHA-256 del payload firmado, `verifyEvent` final.
- **Doble auth en `/send`**: NIP-98 del pubkey + `registrationSecret` que debe existir y matchear el pubkey.
- **`validateNotificationUrl`** (154-169): fuerza origin `acars.pub` + path whitelist (`/corporate`, `/network`, `/fleet`, `/airport/`, `/aircraft/`). Anti-phishing/open-redirect.
- **Origin allowlist** estricta (81-129).
- **Rate limit por IP** (30/min) + auth Nostr obligatoria = capas.
- **Prune stale registrations**: si push service responde 410/404/unregistered, borra el registro (1006-1010, 1188-1190).
- **Idempotencia de entrega** con `INSERT OR IGNORE` en `notification_deliveries` (680-687).

### Service worker defensivo

`notification-sw.js` re-valida origin + path whitelist (`getSafeNotificationUrl` líneas 9-29) antes de abrir URL desde el payload push. Defensa en profundidad: el Worker ya valida, el SW también.
